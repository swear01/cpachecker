\begin{abstract}
Predicate abstraction with CEGAR and lasso-based termination both fail in the same place: a
loop needs a \emph{relational} fact---an invariant coupling variables, or a ranking measure
outside a fixed template---that no single counterexample path or synthesis family exposes.
We present \tool{}, an LLM oracle for \cpa{} governed by one rule: \emph{the model proposes,
the verifier decides, and nothing unvalidated reaches the engine}. The same
\emph{verified-candidate-provider} shell covers two artifacts with \emph{different} gates.
For safety, loop predicates must pass contract and vocabulary checks and are injected only as
precision refinements at loop heads (monotone, so useless suggestions cannot yield a wrong
\textsc{True}); an SMT entailment tier was implemented but dropped after ablation hurt overall
performance. For termination, each ranking function and supporting invariant must discharge a
four-condition SMT proof on the lasso before use. On 764 SV-COMP Loops ReachSafety tasks,
\tool{} solves 29 more tasks than base predicate analysis in isolation ($224{\to}253$); on the
\texttt{svcomp26} portfolio a naive deployment adds $+7$ ($486{\to}493$); a stock-first schedule
and peel trigger add $+11$ each in controlled full-set arms ($493{\to}504$, 0 wrong;
\Cref{tab:safety}). Termination adds four tasks ($80{\to}84$, 0 lost, 0 wrong) on 146
integer-termination benchmarks. We report these gains together with their limits: most
residual safety tasks are nonlinear and out of scope for a linear predicate engine, and the
termination lift has a small, characterised ceiling.

\keywords{Software verification \and CEGAR \and Predicate abstraction \and
Termination \and Ranking functions \and Large language models.}
\end{abstract}

\section{Introduction}
\label{sec:intro}

Software verification has two mature loop-centric paradigms, both implemented at scale in
\cpa{}~\cite{cpachecker2011} and competitive at SV-COMP~\cite{svcomp2022}: predicate
abstraction with CEGAR~\cite{cegar2003,predabstraction1997,slam2002}, and termination via
lasso-based ranking-function synthesis~\cite{ranking2004,ultimate2014}. Each stalls when
the proof needs a relational fact the built-in search never surfaces. CEGAR refines from
Craig interpolants~\cite{interpolation2003} along \emph{one} spurious counterexample (CE)
path; if the invariant couples variables across iterations---$x+y=n$ in our running
example---interpolation discovers $\{y=n\}$, then $\{y=n-1\wedge x=1\}$, one conjunct per
unrolling, and the proof diverges. Termination analysis is symmetric: template synthesis
~\cite{ultimate2014} only finds measures in a fixed family and returns \textsc{Unknown} when
the true ranking function lies outside it.

\paragraph{A running example.}
\Cref{lst:example} is a counting loop. Safety needs the relational invariant $x+y=n$;
termination needs the ranking function $f=y$. Stock predicate CEGAR on this task times out
after 69 refinements at \textsc{Unknown}: the closing invariant never appears on any single CE
trace. A language model can plausibly \emph{name} both artifacts from loop structure alone.
The obstacle is trust---a bogus predicate injected into the abstract domain could turn a
spurious argument into a wrong \textsc{True}. Using LLM output directly is not an option.

\begin{figure}[t]
\begin{lstlisting}
x = 0; y = n;                 // n is an unknown non-negative input
while (y > 0) { x++; y--; }   // safety needs  x + y == n
assert(x == n);               // termination needs ranking f = y
\end{lstlisting}
\vspace{-6pt}
\caption{Running example. One loop exposes both gaps: a relational \emph{predicate}
($x{+}y{=}n$) for the safety proof, and a \emph{ranking function} ($f{=}y$) for the
termination proof.}
\label{lst:example}
\end{figure}

\tool{} treats the LLM as a \emph{verified-candidate provider}: it proposes artifacts; the
existing verifier decides the verdict; only checked candidates enter the engine
(\Cref{sec:approach}). The architecture is \emph{artifact-agnostic}---one integration pattern,
two gates. \textbf{Safety.} After the first spurious CE, \tool{} queries \llm{} with a
context pack (source, CE formula, loop-head labels), validates each JSON predicate through
contract and vocabulary checks, and injects survivors at loop heads as precision-only
refinements. Adding predicates refines the abstraction monotonically, so even a useless
suggestion cannot create a wrong \textsc{True}; we also implemented block entailment (L3) for
interpolant strengthening but do not use it---ablation on \texttt{full\_scalar} hurt solved
count and PAR-2. \textbf{Termination.} When template synthesis fails on a lasso, the LLM
proposes a ranking function and optional supporting invariant; a four-condition SMT discharge
on the lasso transition must succeed before the engine accepts the measure. No Tier in which
the LLM output is trusted as a verdict or unchecked assumption is permitted.

We evaluate this split honestly on SV-COMP-scale benchmarks (\Cref{sec:eval}): where predicate
injection helps, where \emph{when} to fire matters as much as \emph{what} to propose, and
where linear machinery still bounds the method. This paper contributes:

\begin{enumerate}
  \item \textbf{A verified-candidate-provider architecture} (\Cref{sec:approach}): Tier~S
        only---the LLM proposes, artifact-specific checks gate use, the verifier decides; Tier~X
        (direct LLM verdict) is forbidden.
  \item \textbf{A predicate oracle} for CEGAR: CE-triggered query, L1/L2 validation cascade,
        and a divergence-aware firing schedule (stock-first guard plus peel trigger when CEGAR
        is unrolling a loop); L3 entailment omitted after ablation.
  \item \textbf{A ranking-function oracle} for termination: on template failure, propose
        $(f,I)$ and accept only after a four-condition SMT proof on the lasso.
  \item \textbf{An empirical study with stated limits} (\Cref{sec:eval,sec:discussion}):
        +29 tasks on Loops ReachSafety in isolation ($224{\to}253$), +7 on the competition
        portfolio with naive deployment ($486{\to}493$) and up to +18 with stock-first plus peel
        ($493{\to}504$ in controlled schedule arms), +4 on NoOverflow and +4 on termination plus ablations showing CE
        context is necessary and that schedule choice matters far more on the isolated worker
        than inside the portfolio.
\end{enumerate}

\section{Background}
\label{sec:background}

\paragraph{Predicate abstraction and CEGAR.}
A predicate abstraction tracks the program over a finite set $\Pi$ of Boolean predicates.
\cpa{} model-checks the abstraction; on a counterexample it checks feasibility, and if the
CE is \emph{spurious}, refinement extracts interpolants and adds new predicates to $\Pi$,
monotonically refining the abstraction. The abstraction is always a sound
over-approximation, so a proof on the abstraction is a proof on the program. Large-block
encoding summarises straight-line code between abstraction points, reducing the number of
abstraction queries.

\paragraph{Lasso-based termination.}
To prove termination, \cpa{} searches for a \emph{lasso}: a stem path reaching a loop, plus a
cyclic path through it. For a lasso it tries to synthesise a \emph{ranking function} $f$---an
integer measure that is bounded below and strictly decreases on every iteration; a valid $f$
proves the lasso cannot recur forever~\cite{ranking2004,ultimate2014}. Synthesis searches a
fixed template family; if no template fits, the lasso is reported \textsc{Unknown}.
A separate non-termination check (omitted here) handles \textsc{False}.

\section{Approach}
\label{sec:approach}

\subsection{The Verified-Candidate-Provider Principle}

\tool{} permits the LLM exactly one role and forbids another (\Cref{tab:tiers}). In
\emph{Tier~S}, the LLM proposes a candidate artifact that must pass artifact-specific checks
before use---L1/L2 validation for predicates, a four-condition SMT discharge for ranking
functions---and only then reaches the engine; a wrong proposal merely wastes CPU and can never
cause a wrong verdict. \emph{Tier~R} would let the LLM choose resources or routing only (verdict
still decided by the engine). \emph{Tier~X}---trusting LLM output as a verdict or unchecked
assumption---is forbidden. Everything below is Tier~S.

\begin{table}[t]
\caption{Soundness tiers for LLM intervention. \tool{} uses only Tier~S.}
\label{tab:tiers}
\centering
\begin{tabular}{lll}
\toprule
Tier & LLM role & Worst case on error \\
\midrule
S (used) & propose candidate; checks gate use & wasted CPU; never a wrong verdict \\
R        & pick resource/strategy only         & slower; verdict unaffected \\
X (forbidden) & output trusted as verdict      & \emph{wrong verdict} \\
\bottomrule
\end{tabular}
\end{table}

\subsection{Predicate Oracle (Safety)}
\label{sec:pred}

\tool{} intercepts CEGAR at one point: immediately after the \emph{first} spurious CE, before
interpolation. This is the earliest moment with a concrete, property-relevant execution to
reason about. \tool{} builds a \emph{context pack}, queries the LLM, validates the response,
and injects survivors at loop heads; standard CEGAR then resumes (\Cref{fig:pipeline}).

\paragraph{Context pack.} Three components: (i)~the stripped C source (global structure,
declarations, loop topology); (ii)~the spurious CE as an SMT-LIB2 block formula
$\varphi_1\wedge\cdots\wedge\varphi_k=\bot$ with SSA renaming, exposing concrete per-iteration
state; and (iii)~the CFA loop-head labels, which double as the only legal injection targets,
so hallucinated locations are rejected by construction.

\paragraph{Validation cascade.} Every proposed predicate must pass \textbf{L1 (contract)}
and \textbf{L2 (vocabulary)} or be silently discarded. L1 requires valid JSON, a recognised
loop-head key, and a syntactically valid C Boolean expression. L2 requires every free variable
to be in scope at the target loop head, killing the common ``undeclared variable'' hallucination.
We also implemented \textbf{L3 (SMT entailment)} for block-wise classification but do not use it:
ablation on \texttt{full\_scalar} favoured L1/L2-only injection, so all runs in \Cref{sec:eval} keep
L3 off. Survivors of L1/L2 are added to the PredicateCPA precision; adding predicates only refines the
abstraction, so the CEGAR soundness invariant is preserved unconditionally.

\paragraph{Configuration.} \tool{} uses \llm{} with chain-of-thought \emph{disabled}:
predicate expressions are short, so reasoning traces add 50--90\,s of latency without usable
output, whereas non-thinking returns a JSON predicate map at $2.4$\,s median latency---small
within a 300\,s budget.

\subsection{Ranking-Function Oracle (Termination)}
\label{sec:rank}

The same role transfers to termination with a different artifact. When lasso-based template
synthesis returns \textsc{Unknown} for a lasso, \tool{} asks the LLM for one or more candidate
ranking functions, each with an optional \emph{supporting invariant} $I$ (the LLM is told $f$
must be provably non-negative, and to supply the invariant that bounds it if needed). A
candidate $(f,I)$ is parsed into a linear integer term and certified against the lasso
transition relation $T(x,x')$ by four SMT unsatisfiability checks:
\begin{align*}
\text{initiation: } &\textit{Stem}\Rightarrow I(x_{\text{entry}}) &
\text{bounded: } &I(x)\wedge T(x,x')\Rightarrow f(x)\ge 0\\
\text{consecution: } &I(x)\wedge T(x,x')\Rightarrow I(x') &
\text{decrease: } &I(x)\wedge T(x,x')\Rightarrow f(x')<f(x)
\end{align*}
When $I=\mathit{true}$ the first two are trivial and this reduces to a pure ranking check. If
all four hold, $(f,I)$ \emph{soundly} proves the lasso terminates and is handed to the
termination engine exactly as a template-synthesised argument would be; otherwise the
candidate is discarded. Soundness is immediate and stronger than in the predicate case: $I$
is \emph{verified inductive} (not assumed), and a candidate for a genuinely non-terminating
lasso cannot pass the decrease check, so the oracle can never turn a non-terminating program
into \textsc{True}. The loop transition is read on the JavaSMT side of the lasso construction,
so the four checks run with no translation to the synthesiser's term representation.

\section{Evaluation}
\label{sec:eval}

\paragraph{Setup.} All runs use \cpa{} with \tool{} extensions, a per-task limit (300\,s
unless noted), and \llm{} (non-thinking, temperature 0) queried at most once per loop. We
report tasks \emph{solved} (a definite \textsc{True}/\textsc{False} verdict), PAR-2 (lower is
better), and \emph{wrong} verdicts (soundness violations). Our main safety evaluation is on
SV-COMP Loops ReachSafety (764 tasks); \Cref{sec:generalisation} reports two generalisation
checks---NoOverflow and termination---at the same per-task limit. We write \emph{stock} for the
unmodified \cpa{} configuration (no \tool{} extensions), and \texttt{svcomp26} for the full
SV-COMP competition-portfolio configuration used in all portfolio rows. ReachSafety results
(\Cref{tab:safety}) follow two tracks: \emph{(i)}~the predicate worker in isolation (mechanism
and schedule decomposition); \emph{(ii)}~the \texttt{svcomp26} portfolio (saturation and
when-to-fire deployment on the same config base). Across \emph{every} configuration in this
section \tool{} produced \textbf{zero wrong verdicts} (no soundness violation); we therefore omit
a wrong-verdict column from the tables and state soundness once here.

\subsection{ReachSafety Evaluation}
\label{sec:scheduling}

Our safety evaluation proceeds in two tracks (\Cref{tab:safety}). Track~\emph{(i)} isolates the
predicate oracle on the \texttt{predicateAnalysis} worker and decomposes the firing schedule.
Track~\emph{(ii)} embeds the oracle in the \texttt{svcomp26} portfolio: Step~1 measures
saturation relative to stock; Steps~2--3 vary only \emph{when} the oracle fires on the same
portfolio configuration. The $\Delta$ column is cumulative within each track (--- marks the
track baseline).

\paragraph{Predicate oracle.} On the running example, the oracle proposes nine predicates including
\texttt{x+y==n}; five clear the cascade, and CEGAR then converges in 2 refinements at 3.9\,s
instead of timing out after 69 (a 95\% wall-time and 97\% refinement reduction).

\paragraph{Firing schedule.} A second lever, orthogonal to \emph{which} predicates the oracle
proposes, is \emph{when} it fires. On the isolated worker, the v1.7.1 default
(\texttt{every\_n\_or\_interval} with peel threshold~4) solves only 236 tasks ($+12$): peel
misfires on converging tasks whose CE trace crosses four loop-head visits
(\texttt{divbin}, \texttt{hard-u}). In the \texttt{svcomp26} portfolio, parallel sibling analyses
cover many of those easy wins, so the same triggers target genuine divergence instead
(\Cref{tab:safety}, track~\emph{(ii)}, Steps~2--3). The naive policy---fire on the first
spurious CE---is suboptimal in two opposite ways. Firing on a task stock would solve in one or two
refinements injects noisy-but-correct predicates that derail it: \texttt{nested-3} grows from 2
refinements to dozens and times out at \textsc{Unknown}. Firing too late lets stock burn the
(CPU-time) budget on a diverging loop before the LLM helps, ending in an incomplete analysis:
\texttt{heapsort}, a direct LLM win when fired early, is lost when the call is delayed. The
principle that resolves both is \emph{fire only when stock is not converging}. We implement it in
two stages: a \emph{stock-first} schedule never fires at refinement~\#1 and otherwise fires after
$K{=}10$ refinements or $D{=}15$\,s of wall-clock; a \emph{peel} trigger then fires \emph{early}
(refinement~\#2$+$) when the counterexample passes loop heads at least four times---the loop is
being unrolled one iteration per refinement, which is exactly where a single relational predicate
breaks the cycle. Converging tasks peak at three loop-head visits and never fire; diverging tasks
cross four at refinement \#2--\#4.

Track~\emph{(i)} shows that firing at refinement \#1 with a spurious CE adds 29 solves
($224{\to}253$); firing at \#0 with source code only (\emph{source-prior}) stays at 224, so CE
context---not static program understanding---drives the gain. The v1.7.1 default (last row) drops
to $+12$: peel=4 is the main regress on the isolated worker ($252{\to}236$). Track~\emph{(ii)}
Step~1 shows portfolio saturation: the same oracle with fire-at-\#1 adds only $+7$
($486{\to}493$) because sibling workers already cover many predicate-only wins. Steps~2--3 vary
only \emph{when} the oracle fires on the competition portfolio; on controlled full-set arms the
schedule ladder is $482{\to}493{\to}504$ (+11 per stage, 0 wrong). Step~2 recovers regressions
such as \texttt{nested-3} without changing the Step~1 solve count on the saturated deployment;
Step~3 adds another +11 by firing early on diverging loops (\texttt{heapsort}, \texttt{nested9}).
Case studies below illustrate the mechanism. Only firing time moves in Steps~2--3---every
predicate still passes the L1/L2 cascade.

\paragraph{Ablation: CE context is necessary.} The refinement-\#0 row in
\Cref{tab:safety} (\emph{source-prior}: LLM at analysis start, source only, same validation
cascade) solves 224 tasks---identical to stock---whereas refinement \#1 reaches 253. The LLM's
value is therefore relational reasoning over the concrete counterexample, not pattern matching on
source alone; CE-guided refinement is the correct integration point.

\subsection{Case Studies}
\label{sec:casestudies}

\paragraph{A predicate win: \texttt{count\_up\_down-1}.} This is the running example of
\Cref{lst:example}. Stock predicate analysis discovers one conjunct per loop unrolling and times
out after 69 refinements. On the first spurious CE, \tool{} proposes four predicates---$y=n-x$
(the relational invariant the example needs), $x\ge 0$, $y\le n$, and $x>0$; all four pass
L1/L2, and CEGAR then closes the proof in \textbf{2 refinements at 3.9\,s}---a 95\%
wall-time and 97\% refinement reduction from a single oracle call.

\paragraph{Why timing decides it: \texttt{heapsort} vs.\ \texttt{nested-3}.} These two tasks show
the scheduling principle concretely. \texttt{heapsort} diverges under stock and needs the oracle
\emph{early}: the peel trigger detects the loop being unrolled at refinement~\#4 and fires,
injecting index bounds ($1\le i,j,l\le n$) that close the proof; with a count/time-only schedule
the call arrives too late and the analysis exhausts its CPU budget at \textsc{Unknown}.
\texttt{nested-3} is the mirror image: stock converges in 2 refinements, so the oracle must
\emph{not} fire---an early call injects the mutually exclusive facts $\mathit{st}=0$ and
$\mathit{st}=1$, each individually certified but jointly noisy, blowing the proof up to dozens of
refinements and a timeout. The divergence-aware schedule fires on the first and stays silent on
the second; this asymmetry motivates Steps~2--3 in \Cref{tab:safety}.

\subsection{Generalisation}
\label{sec:generalisation}

The verified-candidate-provider role is artifact-agnostic by design; we tested two
generalisations beyond the main Loops ReachSafety study. Both use the same 300\,s limit and
produce \textbf{zero wrong verdicts}; the gains are real but modest compared with the
reachability results above.

\paragraph{NoOverflow (predicate oracle).} NoOverflow checking routes through the same
predicate-refinement hook as reachability---a config-only flip on the overflow predicate
component, with no Java or prompt changes. On \texttt{no\_overflow\_scalar} (452 tasks) under
the svcomp26 overflow portfolio, stock solves 362 and \tool{} solves 366 ($+4$). At a 120\,s
limit the lift was $+6$; two tasks stock catches up by 300\,s, leaving four sound
\tool{}-only wins. Injected predicates are still spurious-CE-driven bounds and ranges relevant
to overflow avoidance rather than reachability invariants.

\paragraph{Termination (ranking-function oracle).} Termination uses a different artifact on a
different injection point: when lasso-based template synthesis returns \textsc{Unknown}, the
LLM proposes ranking functions certified by the four-condition check of \Cref{sec:rank}. We
evaluate on \texttt{termination\_scalar} (146 integer-termination tasks, lasso route in
isolation): stock solves 80; with the ranking oracle it solves 84 ($+4$, \textbf{0 lost}, all
21 non-terminating tasks stay \textsc{False}). The four new solves are SMT-certified measures
outside the template family, e.g.\ $f=n-i$, $f=k-i$, $f=x$, and---with a co-synthesised
supporting invariant---$f=y_1+y_2$ with $I=(y_1>0\wedge y_2>0)$. Stock solves the same 80 at
both 60\,s and 300\,s, so the residual failures are template-\emph{unsolvable}, not
time-limited. Portfolio-net gain in the real competition branch is $\le 4$ because a parallel
termination-to-safety worker has no LLM path (\Cref{sec:discussion}).

\section{Discussion and Limitations}
\label{sec:discussion}

We report the gains \emph{with} their boundaries; the boundaries are as informative as the
gains.

\paragraph{Sound predicates can still be noisy hints.} Validation guarantees that an accepted
predicate is \emph{correct}, not that it is \emph{useful}. On \texttt{nested-3}, the LLM
proposes \texttt{st==0} and \texttt{st==1}; both are individually satisfiable and accepted, but
their joint injection splits the abstract state and enlarges the search, turning a 2-refinement
stock proof into a timeout. The divergence-aware schedule (\Cref{sec:scheduling}) addresses this
directly---it does not fire on tasks stock is already converging on, so \texttt{nested-3} is no
longer derailed; a mutual-consistency check across injected predicates would help further, at
extra SMT cost.

\paragraph{Portfolio vs.\ isolation.} The predicate oracle adds 29 solves on the isolated
worker but only $+7$ on the saturated competition portfolio ($486{\to}493$): parallel sibling
strategies already close many predicate-only proofs. Scheduling still matters: controlled
full-set arms gain +11 per stage ($482{\to}493{\to}504$), recovering \texttt{nested-3}-type
regressions and then early-divergence wins, while the isolated worker amplifies schedule mistakes
($252{\to}236$ for peel=4). \emph{When} to fire is therefore decisive in isolation and still
material in portfolio deployment, even when the saturated solve count moves more slowly.

\paragraph{The reachability gain is also bounded.} After the scheduling improvement, the cheap
predicate-mechanism levers are exhausted. Of the remaining unsolved tasks, roughly 70\% are
\emph{nonlinear-arithmetic} instances (the SV-COMP \texttt{nla-digbench} family)---e.g.\ \texttt{cohencu} asserts $x=n^3$ and
$y=3n^2{+}3n{+}1$---whose proofs need polynomial invariants that linear predicate abstraction
cannot express and whose nonlinear SMT queries cost tens of seconds each; the LLM, riding on a
linear engine, essentially never converts them (9 of $\sim$480 across the family). These are out
of scope for the mechanism, not a tuning failure. The rest sit at a predicate-quality ceiling:
tasks that fire several rounds yet do not converge, where a sharper prompt is unlikely to help
(consistent with the CE-context ablation). Further reachability gains therefore need a new
capability---nonlinear invariant synthesis or a new injection point---not more prompt/schedule tuning.

\paragraph{The termination gain has a small, characterised ceiling.} On the 56 stock-\textsc{Unknown}
terminating tasks, the oracle only \emph{fires} on 9 (winning 4): \textbf{40 never produce a lasso}
at all---they are pointer/array/string loops where the lasso safety analysis gives up before the
injection point is reached---and so are structurally beyond this oracle. We tried three cheap levers
to raise the gain on the tasks that do fire and \emph{none helped}: a boundedness-pushing prompt
made first-round results worse ($4\to3$); a verify-and-repair loop that feeds the failing SMT check
back to the LLM added nothing ($+0$); and injecting the stem formula as ``loop-entry facts'' was
worse still ($4\to2$), as the SSA-indexed dump is noise the model cannot use. The lesson mirrors our
predicate ablation: extra context and instructions degraded the model, and the plain source with a
simple prompt was best. The remaining failures are not a context problem but the limit of
single-shot \emph{linear} ranking-function guessing.

\paragraph{Isolated vs.\ portfolio gain.} The $+4$ is measured on the lasso route \emph{in
isolation}, for clean attribution. In the real competition branch the lasso route runs in
parallel with a termination-to-safety strategy that has \emph{no} LLM path; that strategy may
independently solve some of the four wins, so the portfolio-net gain is $\le 4$. We therefore
present $+4$ as the oracle's contribution to the lasso route, not a competition-category delta,
and the termination benchmark itself is a hook-favourable integer subset, not the full category.

\paragraph{Online LLM dependency.} \tool{} calls an external API; the SV-COMP setting is
network-isolated. The artifact is reproducible offline---it bundles the recorded experiment
outputs and analysis scripts, so every reported number regenerates without network access,
while live re-runs need an API key---but a competition \emph{submission} would still need a
local or distilled model or a pre-computed candidate cache.

\paragraph{\textsc{False}-path blindness.} Both oracles improve only \textsc{True} counts. The
predicate oracle supplies proof-supporting invariants, not bug witnesses; the ranking oracle proves
termination, never non-termination. Extending the provider to \textsc{False} needs a different
\emph{artifact}: not a predicate but a concrete violating input, certified by \emph{execution}
rather than an SMT proof---the propose--certify--decide principle still applies, but with a
test-execution back-end instead of predicate abstraction. This also sidesteps the nonlinear wall,
since reaching a bug requires running one input, not proving an invariant. We leave it to future
work; it is a genuinely different engine, not a variant of the predicate oracle.

\section{Related Work}
\label{sec:related}

LLM-guided invariant generation is active. CIll~\cite{cill2026} uses counterexample context to
guide an LLM for hardware model checking---like \tool{}, it exploits the CE and validates before
use, but targets transition-system invariants rather than software CEGAR. Hybrid LLM+SMT loop-invariant
synthesis~\cite{loopinvariant2025} and Quokka~\cite{quokka2025} alternate LLM generation with solver
checking, but as standalone synthesis outside a running verifier; \tool{} instead injects at the CEGAR
loop head, CE-triggered. IC3-based protocol invariant synthesis~\cite{ic3llm2026} applies the same
propose-and-check oracle to distributed protocols. Neuro-symbolic proof
generation~\cite{neurosymbolic2026} drives interactive provers with LLM hints, and agentic model
checking~\cite{agenticmc2026} wraps a checker in an autonomous LLM loop; \tool{} is deliberately
lighter---one structured oracle call, no autonomous replanning---which shrinks the LLM attack surface.
Against all of these, our distinguishing point is breadth of \emph{one} soundness role: the same
verified-candidate provider supplies both predicates (safety) and ranking functions (termination).
\tool{} builds directly on CEGAR~\cite{cegar2003}, predicate abstraction~\cite{predabstraction1997},
interpolation~\cite{interpolation2003}, and lasso-based ranking-function
synthesis~\cite{ranking2004,ultimate2014} in \cpa{}~\cite{cpachecker2011}.

\section{Conclusion}
\label{sec:concl}

\tool{} shows that an LLM can be integrated into \cpa{} as a \emph{sound} verified-candidate
provider: the model proposes, artifact-specific checks gate use, and the verifier always decides
the verdict. The same shell covers predicates for safety and ranking functions for termination,
with different validation gates and zero wrong verdicts across every configuration we report.

On Loops ReachSafety the story splits cleanly by deployment context. In \emph{isolation}, the
predicate oracle adds 29 solves ($224{\to}253$) and an ablation proves that CE context, not
source code alone, drives the gain; schedule choice is then decisive---the v1.7.1 peel default
costs 17 solves on the isolated worker ($252{\to}236$). Inside the competition
\emph{portfolio}, sibling analyses absorb much of that lift: naive deployment adds $+7$
($486{\to}493$), and controlled schedule arms reach 504 (+18 vs.\ stock, +11 per stage over
fire-at-\#1 $\to$ stock-first $\to$ peel). \emph{When} to fire therefore matters most where the
predicate worker stands alone; in competition configuration it still adds measurable headroom on
top of saturation. Beyond reachability, NoOverflow and termination each add four sound solves
(+4, 0 lost).

We state the ceilings as plainly as the wins. Residual reachability tasks are dominated by
nonlinear arithmetic outside a linear predicate engine; termination gains are capped by how often
the lasso route is reached at all; and neither oracle targets \textsc{False}. An artifact with
source, configurations, benchmark lists, recorded outputs, and evaluation scripts is publicly
available;\footnote{Archived at \url{https://doi.org/10.5281/zenodo.20745141}; development
repository at \url{https://github.com/swear01/cpachecker}.} all tables regenerate offline, and
live re-runs need an API key.

\section{Future Work}
\label{sec:future}

The boundaries above suggest concrete next steps rather than more tuning of the current hooks.
For termination, a \emph{structurally earlier} injection point is needed to reach pointer/array/string
loops before the lasso safety analysis gives up. For safety, gains beyond the linear predicate engine
require a different capability---nonlinear invariant synthesis---or a new injection point altogether.
Extending the provider to \textsc{False} is a separate direction: certify a concrete bug-triggering
input by execution rather than an SMT proof, which also sidesteps the nonlinear wall. Finally, a local
or distilled model would remove the online-API dependency for competition submission.
