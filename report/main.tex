\begin{abstract}
Counterexample-guided abstraction refinement (CEGAR) with predicate abstraction and
lasso-based termination analysis are two pillars of automated software verification, yet
both stall on a common task: discovering the \emph{relational} facts that span a loop.
Craig interpolation reasons about one counterexample path and cannot synthesise
multi-variable loop invariants; template-based ranking-function synthesis only finds
measures inside a fixed template family. We present \tool, which augments \cpa{} with a
large-language-model (LLM) oracle that follows a single principle: \emph{the LLM
proposes, an SMT check certifies, and the verifier decides}. We show that this
``verified-candidate provider'' role is \emph{artifact-agnostic}: the same architecture
supplies (i)~loop predicates for safety proofs and (ii)~ranking functions with supporting
invariants for termination proofs, and in both cases no unvalidated LLM output can change a
verdict. On 764 SV-COMP Loops ReachSafety tasks, \tool{} predicates solve 29 more tasks
than the base predicate analysis ($224\to253$) and 7 more in the full competition
portfolio; a competition-grade combined run over ReachSafety and NoOverflow gains 19 tasks
with zero wrong verdicts. Beyond \emph{what} to propose, \emph{when} to fire matters: a
divergence-aware schedule that invokes the oracle only when CEGAR is unrolling a loop---never on
the first counterexample---adds a further 22 solved tasks ($482\to504$) in the svcomp27 portfolio,
again with zero wrong verdicts. For termination, an LLM ranking-function oracle that fires when
template synthesis fails solves 4 additional tasks ($80\to84$, 0 lost, 0 wrong) on 146
integer-termination tasks. We report these gains \emph{with} their limits: an ablation
shows the predicate oracle is worthless without counterexample context; the termination
gain has a small, clearly characterised ceiling; and the cheap prompt/repair levers we
tried did not raise it. The contribution is a clean, sound, and honestly-bounded
generalisation of LLM-guided refinement across verification artifacts.

\keywords{Software verification \and CEGAR \and Predicate abstraction \and
Termination \and Ranking functions \and Large language models.}
\end{abstract}

\section{Introduction}
\label{sec:intro}

Predicate abstraction with CEGAR~\cite{cegar2003,predabstraction1997,slam2002} and
termination analysis via lasso-based ranking-function synthesis~\cite{ranking2004,ultimate2014}
are two of the most successful paradigms in automated software verification, both
implemented at scale in \cpa{}~\cite{cpachecker2011} and routinely competitive at
SV-COMP~\cite{svcomp2022}. They share a structural weakness at the loop. CEGAR refines its
predicate abstraction from Craig interpolants~\cite{interpolation2003}, which reason about a
\emph{single} counterexample (CE) path; when the property needs a \emph{relational}
invariant relating several variables across all iterations, interpolation produces one
predicate per unrolling and never converges. Termination analysis dually fails: lasso-based
synthesis~\cite{ultimate2014} only discovers ranking functions expressible by its fixed
template family (affine and nested), and returns \textsc{Unknown} when the terminating
measure lies outside it.

\paragraph{A running example.}
\Cref{lst:example} shows a counting loop. Proving the assertion \emph{safe} requires the
relational invariant $x+y=n$; proving the loop \emph{terminates} requires the ranking
function $f=y$ (non-negative and strictly decreasing). Stock CEGAR diverges on the safety
proof: it discovers $\{y=n\}$, then $\{y=n-1\wedge x=1\}$, one conjunct per unrolling, and
after 69 refinements times out at \textsc{Unknown}. The closing invariant $x+y=n$ is never
seen, because no single CE trace makes it visible.

\begin{figure}[t]
\begin{lstlisting}
x = 0; y = n;                 // n is an unknown non-negative input
while (y > 0) { x++; y--; }   // safety needs  x + y == n
assert(x == n);               // termination needs ranking f = y
\end{lstlisting}
\vspace{-6pt}
\caption{Running example. One loop exposes both gaps: a relational \emph{predicate}
($x{+}y{=}n$) for the safety proof, and a \emph{ranking function} ($f{=}y$) for the
termination proof.}
\label{lst:example}
\end{figure}

A language model pre-trained on code can plausibly name $x+y=n$ and $f=y$ from structural
pattern matching. The obstacle is trust: an incorrect predicate, injected into the abstract
domain, could make CEGAR report a wrong \textsc{True}, destroying the soundness that gives
verification its value. Using LLM output directly is not an option.

\tool{} resolves this with one principle---\emph{the LLM proposes, an SMT check certifies,
the verifier decides}---and our central observation is that this principle is
\emph{artifact-agnostic}. The LLM is a \emph{verified-candidate provider}: it proposes a
candidate artifact, a sound engine certifies it, and only then is it used. Instantiating the
same role for two different artifacts---predicates (safety) and ranking functions
(termination)---reuses one soundness argument across two paradigms. This paper contributes:

\begin{enumerate}
  \item \textbf{A verified-candidate-provider architecture} (\Cref{sec:approach}) with an
        explicit soundness taxonomy (\emph{Tier~S}: verified candidate; \emph{Tier~R}:
        resource/routing only; \emph{Tier~X}: direct verdict---forbidden). \tool{} is
        strictly Tier~S.
  \item \textbf{A predicate oracle} for CEGAR: a CE-triggered query and a three-tier
        validation cascade that injects only SMT-certified predicates at loop heads, plus a
        \emph{divergence-aware firing schedule} (fire only when CEGAR is unrolling a loop, never
        on the first counterexample) that adds $+22$ solved tasks at zero soundness cost.
  \item \textbf{A ranking-function oracle} for termination: when template synthesis fails,
        the LLM proposes a ranking function and a supporting invariant, both discharged by a
        four-condition SMT check before use.
  \item \textbf{An honest empirical study} (\Cref{sec:eval,sec:discussion}): strong predicate
        gains (29/7/19 tasks, and a further $+22$ from divergence-aware scheduling, 0 wrong) with
        an ablation proving CE context is necessary; a small but sound termination gain (+4, 0
        wrong, 0 lost); and a frank account of where the method's ceiling lies and which cheap
        levers failed to raise it.
\end{enumerate}

\section{Background}
\label{sec:background}

\paragraph{Predicate abstraction and CEGAR.}
A predicate abstraction tracks the program over a finite set $\Pi$ of Boolean predicates.
\cpa{} model-checks the abstraction; on a counterexample it checks feasibility, and if the
CE is \emph{spurious}, refinement extracts interpolants and adds new predicates to $\Pi$,
monotonically refining the abstraction. The abstraction is always a sound
over-approximation, so a proof on the abstraction is a proof on the program. Large-block
encoding summarises straight-line code between abstraction points, reducing the number of
abstraction queries.

\paragraph{Lasso-based termination.}
To prove termination, \cpa{} searches for a \emph{lasso}: a stem path reaching a loop, plus a
cyclic path through it. For a lasso it tries to synthesise a \emph{ranking function} $f$---an
integer measure that is bounded below and strictly decreases on every iteration; a valid $f$
proves the lasso cannot recur forever~\cite{ranking2004,ultimate2014}. Synthesis searches a
fixed template family; if no template fits, the lasso is reported \textsc{Unknown}.
A separate non-termination check (omitted here) handles \textsc{False}.

\section{Approach}
\label{sec:approach}

\subsection{The Verified-Candidate-Provider Principle}

\tool{} permits the LLM exactly one role and forbids another (\Cref{tab:tiers}). In
\emph{Tier~S}, the LLM proposes a candidate artifact that a sound engine must certify before
use; a wrong proposal merely wastes CPU and can never cause a wrong verdict. \emph{Tier~R}
would let the LLM choose resources or routing only (verdict still decided by the engine).
\emph{Tier~X}---trusting LLM output as a verdict or unchecked assumption---is forbidden.
Everything below is Tier~S.

\begin{table}[t]
\caption{Soundness tiers for LLM intervention. \tool{} uses only Tier~S.}
\label{tab:tiers}
\centering
\begin{tabular}{lll}
\toprule
Tier & LLM role & Worst case on error \\
\midrule
S (used) & propose candidate; engine certifies & wasted CPU; never a wrong verdict \\
R        & pick resource/strategy only         & slower; verdict unaffected \\
X (forbidden) & output trusted as verdict      & \emph{wrong verdict} \\
\bottomrule
\end{tabular}
\end{table}

\subsection{Predicate Oracle (Safety)}
\label{sec:pred}

\tool{} intercepts CEGAR at one point: immediately after the \emph{first} spurious CE, before
interpolation. This is the earliest moment with a concrete, property-relevant execution to
reason about. \tool{} builds a \emph{context pack}, queries the LLM, validates the response,
and injects survivors at loop heads; standard CEGAR then resumes (\Cref{fig:pipeline}).

\centering

  \draw[->] (val)--(inject); \draw[->] (inject)--(cegar);

\paragraph{Context pack.} Three components: (i)~the stripped C source (global structure,
declarations, loop topology); (ii)~the spurious CE as an SMT-LIB2 block formula
$\varphi_1\wedge\cdots\wedge\varphi_k=\bot$ with SSA renaming, exposing concrete per-iteration
state; and (iii)~the CFA loop-head labels, which double as the only legal injection targets,
so hallucinated locations are rejected by construction.

\paragraph{Validation cascade.} Every proposed predicate must clear three tiers or be
silently discarded. \textbf{L1 (contract)}: valid JSON, a recognised loop-head key, and a
syntactically valid C Boolean expression. \textbf{L2 (vocabulary)}: every free variable is in
scope at the target loop head, killing the common ``undeclared variable'' hallucination.
\textbf{L3 (SMT entailment)}: Z3 confirms the predicate is satisfiable (not trivially false)
and not already entailed by the abstract state, so each accepted predicate is a genuine
refinement. Survivors are added to the PredicateCPA precision; adding predicates only refines
the abstraction, so the CEGAR soundness invariant is preserved unconditionally.

\paragraph{Configuration.} \tool{} uses \llm{} with chain-of-thought \emph{disabled}:
predicate expressions are short, so reasoning traces add 50--90\,s of latency without usable
output, whereas non-thinking returns a JSON predicate map at $2.4$\,s median latency---small
within a 300\,s budget.

\subsection{Ranking-Function Oracle (Termination)}
\label{sec:rank}

The same role transfers to termination with a different artifact. When lasso-based template
synthesis returns \textsc{Unknown} for a lasso, \tool{} asks the LLM for one or more candidate
ranking functions, each with an optional \emph{supporting invariant} $I$ (the LLM is told $f$
must be provably non-negative, and to supply the invariant that bounds it if needed). A
candidate $(f,I)$ is parsed into a linear integer term and certified against the lasso
transition relation $T(x,x')$ by four SMT unsatisfiability checks:
\begin{align*}
\text{initiation: } &\textit{Stem}\Rightarrow I(x_{\text{entry}}) &
\text{bounded: } &I(x)\wedge T(x,x')\Rightarrow f(x)\ge 0\\
\text{consecution: } &I(x)\wedge T(x,x')\Rightarrow I(x') &
\text{decrease: } &I(x)\wedge T(x,x')\Rightarrow f(x')<f(x)
\end{align*}
When $I=\mathit{true}$ the first two are trivial and this reduces to a pure ranking check. If
all four hold, $(f,I)$ \emph{soundly} proves the lasso terminates and is handed to the
termination engine exactly as a template-synthesised argument would be; otherwise the
candidate is discarded. Soundness is immediate and stronger than in the predicate case: $I$
is \emph{verified inductive} (not assumed), and a candidate for a genuinely non-terminating
lasso cannot pass the decrease check, so the oracle can never turn a non-terminating program
into \textsc{True}. The loop transition is read on the JavaSMT side of the lasso construction,
so the four checks run with no translation to the synthesiser's term representation.

\section{Evaluation}
\label{sec:eval}

\paragraph{Setup.} All runs use \cpa{} with \tool{} extensions, a per-task limit (300\,s
unless noted), and \llm{} (non-thinking, temperature 0) queried at most once per loop. We
report tasks \emph{solved} (a definite \textsc{True}/\textsc{False} verdict), PAR-2 (lower is
better), and \emph{wrong} verdicts (soundness violations). Safety benchmarks are SV-COMP Loops
ReachSafety (764 tasks) and a NoOverflow scalar subset (452). Termination is evaluated on
\texttt{termination\_scalar}: 146 integer-termination tasks (125 terminating, 21
non-terminating) drawn from the SV-COMP crafted, crafted-lit, and numeric termination
families. We write \emph{stock} for the unmodified \cpa{} configuration (no \tool{} extensions),
and \texttt{svcomp26}/\texttt{svcomp27} for its full SV-COMP competition-portfolio configurations
of the respective years; the predicate-oracle results use the 2026 portfolio and the later
scheduling study (\Cref{sec:scheduling}) the 2027 one. Across \emph{every} configuration in this
section \tool{} produced \textbf{zero wrong verdicts} (no soundness violation); we therefore omit
a wrong-verdict column from the tables and state soundness once here.

\subsection{Predicate Oracle}

\Cref{tab:safety} (top) shows that on Loops ReachSafety the predicate oracle solves 29 more
tasks than the base predicate analysis ($224\to253$, $+12.9\%$) and lowers PAR-2 from
$428.4$ to $406.5$\,s, with \textbf{zero} wrong verdicts. In the full svcomp26 portfolio the
gain is $+7$ ($486\to493$): smaller, because parallel strategies (symbolic execution,
$k$-induction, value analysis) already cover many tasks the predicate worker uniquely solves
in isolation. A competition-grade combined run (\Cref{tab:safety}, bottom) gains $+15$
ReachSafety and $+4$ NoOverflow, $+19$ total, again with no wrong verdicts; the transfer to
overflow tasks is free, as they share the bounded-counter loop patterns the LLM reasons about.
On the running example, the oracle proposes nine predicates including \texttt{x+y==n}; five
clear the cascade, and CEGAR then converges in 2 refinements at 3.9\,s instead of timing out
after 69 (a 95\% wall-time and 97\% refinement reduction).

\paragraph{Ablation: CE context is necessary.} A \emph{source-prior} variant fires the LLM at
analysis start with source code only (no CE trace), validated and injected through the same
cascade. It solves 224 tasks---\emph{identical to stock}---while full \tool{} (every-N-and-interval,
firing at the first CE) solves 253. The LLM's value is therefore not static pattern matching on source but
\emph{relational reasoning over the concrete counterexample}; CE-guided refinement is the
correct integration point.

\subsection{When to Fire: Divergence-Aware Scheduling}
\label{sec:scheduling}

A second lever, orthogonal to \emph{which} predicates the oracle proposes, is \emph{when} it
fires. The naive policy---fire on the first spurious CE---is suboptimal in two opposite ways.
Firing on a task stock would solve in one or two refinements injects noisy-but-correct
predicates that derail it: \texttt{nested-3} grows from 2 refinements to dozens and times out
at \textsc{Unknown}. Firing too late lets stock burn the (CPU-time) budget on a diverging loop
before the LLM helps, ending in an incomplete analysis: \texttt{heapsort}, a direct LLM win when
fired early, is lost when the call is delayed. The principle that resolves both is
\emph{fire only when stock is not converging}.

We implement it in two stages. A \emph{stock-first} schedule never fires at refinement~\#1 and
otherwise fires after $K{=}10$ refinements or $D{=}15$\,s of wall-clock---giving stock a chance
to converge first. A \emph{peel} trigger then fires \emph{early} (refinement~\#2$+$) precisely
when divergence is visible: when the counterexample passes loop heads at least four times, the
loop is being unrolled one iteration per refinement, which is exactly where a single relational
predicate breaks the cycle. The threshold of four is calibrated from the loop-head-visit
trajectories: converging tasks peak at three visits and never fire, while diverging tasks cross
four at refinement \#2--\#4---far earlier than the count/time triggers would.

\Cref{tab:schedule} reports the effect on the full 764-task Loops set under the svcomp27
portfolio (only the firing schedule changes between rows). The divergence-aware schedule solves \textbf{504} of 764 tasks---\textbf{$+22$} over the
first-spurious baseline, with zero wrong verdicts---and lowers PAR-2 from 231 to 210\,s. The two
triggers contribute in sequence: the stock-first step alone gives $+11$, the peel trigger the
remaining $+11$. This is a pure Tier~R change---only the firing time moves, every predicate is
still SMT-certified---so it composes with the predicate oracle of \Cref{sec:eval}. The residual losses are run-to-run
resource-sensitive noise, not regressions in predicate quality.

\subsection{Case Studies}
\label{sec:casestudies}

\paragraph{A predicate win: \texttt{count\_up\_down-1}.} This is the running example of
\Cref{lst:example}. Stock predicate analysis discovers one conjunct per loop unrolling and times
out after 69 refinements. On the first spurious CE, \tool{} proposes four predicates---$y=n-x$
(the relational invariant the example needs), $x\ge 0$, $y\le n$, and $x>0$; all four clear the
L1--L3 cascade, and CEGAR then closes the proof in \textbf{2 refinements at 3.9\,s}---a 95\%
wall-time and 97\% refinement reduction from a single oracle call.

\paragraph{Why timing decides it: \texttt{heapsort} vs.\ \texttt{nested-3}.} These two tasks show
the scheduling principle concretely. \texttt{heapsort} diverges under stock and needs the oracle
\emph{early}: the peel trigger detects the loop being unrolled at refinement~\#4 and fires,
injecting index bounds ($1\le i,j,l\le n$) that close the proof; with a count/time-only schedule
the call arrives too late and the analysis exhausts its CPU budget at \textsc{Unknown}.
\texttt{nested-3} is the mirror image: stock converges in 2 refinements, so the oracle must
\emph{not} fire---an early call injects the mutually exclusive facts $\mathit{st}=0$ and
$\mathit{st}=1$, each individually certified but jointly noisy, blowing the proof up to dozens of
refinements and a timeout. The divergence-aware schedule fires on the first and stays silent on
the second; this asymmetry is exactly what the $+22$ rests on.

\subsection{Ranking-Function Oracle}

\Cref{tab:term} shows the termination oracle on \texttt{termination\_scalar}. Stock lasso
analysis solves 80 tasks; with the LLM ranking oracle it solves 84---$+4$, with \textbf{0

\section{Discussion and Limitations}
\label{sec:discussion}

We report the gains \emph{with} their boundaries; the boundaries are as informative as the
gains.

\paragraph{Sound predicates can still be noisy hints.} Validation guarantees that an accepted
predicate is \emph{correct}, not that it is \emph{useful}. On \texttt{nested-3}, the LLM
proposes \texttt{st==0} and \texttt{st==1}; both are individually satisfiable and accepted, but
their joint injection splits the abstract state and enlarges the search, turning a 2-refinement
stock proof into a timeout. The divergence-aware schedule (\Cref{sec:scheduling}) addresses this
directly---it does not fire on tasks stock is already converging on, so \texttt{nested-3} is no
longer derailed; a mutual-consistency check across injected predicates would help further, at
extra SMT cost.

\paragraph{The reachability gain is also bounded.} After the scheduling improvement, the cheap
predicate-mechanism levers are exhausted. Of the remaining unsolved tasks, roughly 70\% are
\emph{nonlinear-arithmetic} instances (the SV-COMP \texttt{nla-digbench} family)---e.g.\ \texttt{cohencu} asserts $x=n^3$ and
$y=3n^2{+}3n{+}1$---whose proofs need polynomial invariants that linear predicate abstraction
cannot express and whose nonlinear SMT queries cost tens of seconds each; the LLM, riding on a
linear engine, essentially never converts them (9 of $\sim$480 across the family). These are out
of scope for the mechanism, not a tuning failure. The rest sit at a predicate-quality ceiling:
tasks that fire several rounds yet do not converge, where a sharper prompt is unlikely to help
(consistent with the CE-context ablation). Further reachability gains therefore need a new
capability---nonlinear invariant synthesis or a new injection point---not more prompt/schedule tuning.

\paragraph{The termination gain has a small, characterised ceiling.} On the 56 stock-\textsc{Unknown}
terminating tasks, the oracle only \emph{fires} on 9 (winning 4): \textbf{40 never produce a lasso}
at all---they are pointer/array/string loops where the lasso safety analysis gives up before the
injection point is reached---and so are structurally beyond this oracle. We tried three cheap levers
to raise the gain on the tasks that do fire and \emph{none helped}: a boundedness-pushing prompt
made first-round results worse ($4\to3$); a verify-and-repair loop that feeds the failing SMT check
back to the LLM added nothing ($+0$); and injecting the stem formula as ``loop-entry facts'' was
worse still ($4\to2$), as the SSA-indexed dump is noise the model cannot use. The lesson mirrors our
predicate ablation: extra context and instructions degraded the model, and the plain source with a
simple prompt was best. The remaining failures are not a context problem but the limit of
single-shot \emph{linear} ranking-function guessing.

\paragraph{Isolated vs.\ portfolio gain.} The $+4$ is measured on the lasso route \emph{in
isolation}, for clean attribution. In the real competition branch the lasso route runs in
parallel with a termination-to-safety strategy that has \emph{no} LLM path; that strategy may
independently solve some of the four wins, so the portfolio-net gain is $\le 4$. We therefore
present $+4$ as the oracle's contribution to the lasso route, not a competition-category delta,
and the termination benchmark itself is a hook-favourable integer subset, not the full category.

\paragraph{Online LLM dependency.} \tool{} calls an external API; the SV-COMP setting is
network-isolated. The artifact is reproducible offline---it bundles the recorded experiment
outputs and analysis scripts, so every reported number regenerates without network access,
while live re-runs need an API key---but a competition \emph{submission} would still need a
local or distilled model or a pre-computed candidate cache.

\paragraph{\textsc{False}-path blindness.} Both oracles improve only \textsc{True} counts. The
predicate oracle supplies proof-supporting invariants, not bug witnesses; the ranking oracle proves
termination, never non-termination. Extending the provider to \textsc{False} needs a different
\emph{artifact}: not a predicate but a concrete violating input, certified by \emph{execution}
rather than an SMT proof---the propose--certify--decide principle still applies, but with a
test-execution back-end instead of predicate abstraction. This also sidesteps the nonlinear wall,
since reaching a bug requires running one input, not proving an invariant. We leave it to future
work; it is a genuinely different engine, not a variant of the predicate oracle.

\section{Related Work}
\label{sec:related}

LLM-guided invariant generation is active. CIll~\cite{cill2026} uses counterexample context to
guide an LLM for hardware model checking---like \tool{}, it exploits the CE and validates before
use, but targets transition-system invariants rather than software CEGAR. Hybrid LLM+SMT loop-invariant
synthesis~\cite{loopinvariant2025} and Quokka~\cite{quokka2025} alternate LLM generation with solver
checking, but as standalone synthesis outside a running verifier; \tool{} instead injects at the CEGAR
loop head, CE-triggered. IC3-based protocol invariant synthesis~\cite{ic3llm2026} applies the same
propose-and-check oracle to distributed protocols. Neuro-symbolic proof
generation~\cite{neurosymbolic2026} drives interactive provers with LLM hints, and agentic model
checking~\cite{agenticmc2026} wraps a checker in an autonomous LLM loop; \tool{} is deliberately
lighter---one structured oracle call, no autonomous replanning---which shrinks the LLM attack surface.
Against all of these, our distinguishing point is breadth of \emph{one} soundness role: the same
verified-candidate provider supplies both predicates (safety) and ranking functions (termination).
\tool{} builds directly on CEGAR~\cite{cegar2003}, predicate abstraction~\cite{predabstraction1997},
interpolation~\cite{interpolation2003}, and lasso-based ranking-function
synthesis~\cite{ranking2004,ultimate2014} in \cpa{}~\cite{cpachecker2011}.

\section{Conclusion and Future Work}
\label{sec:concl}

\tool{} shows that an LLM can be a \emph{sound} verified-candidate provider for \cpa{}, and that
this role is artifact-agnostic: the identical propose--certify--decide architecture supplies loop
predicates for safety (29/7/19 more tasks, 0 wrong, with an ablation proving CE context is essential)
and ranking functions for termination (+4, 0 lost, 0 wrong, including a case needing a co-synthesised
supporting invariant). Orthogonally, \emph{when} the oracle fires matters as much as what it
proposes: a divergence-aware schedule that fires only when CEGAR is unrolling a loop adds a further
$+22$ solved tasks ($482\to504$) at zero soundness cost. Equally, we have bounded the method honestly:
the predicate gain shrinks under portfolio saturation and can be hurt by noisy-but-correct predicates
(which the schedule mitigates), and the cheap predicate levers are then exhausted---about 70\% of the
residual unsolved tasks are nonlinear instances out of reach of a linear predicate engine; the
termination gain has a small ceiling, set not by prompt engineering---three cheap levers failed---but
by the injection point, since 40 of 56 target loops never reach the oracle. The clearest future
directions follow from these boundaries: for termination, a \emph{structurally earlier} injection point
that reaches pointer/array loops before the lasso analysis gives up; for safety, a different engine for
what the predicate mechanism cannot reach---nonlinear invariant synthesis, or an execution-based
\textsc{False} oracle that certifies a concrete bug-triggering input by running it (which also
sidesteps the nonlinear wall). A local or distilled model would remove the online-API dependency for
competition use. The artifact---source,
configurations, benchmark lists, recorded experiment outputs, and evaluation
scripts---is archived at \url{https://doi.org/10.5281/zenodo.20745141} (DOI
\texttt{10.5281/zenodo.20745141}), with the development repository at
\url{https://github.com/swear01/cpachecker}; all reported tables regenerate offline from the
recorded outputs, and the experiments can be re-run live with an API key.
